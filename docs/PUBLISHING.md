# 上传 GitHub 前

这份目录从运行工作区按允许清单导出，没有继承工作区Git历史，防止历史中夹带私有内容。原始代码和数据没有被删除。

1. 决定仓库公开/私有。两种都不要提交密钥；曾提交过的密钥需要轮换，删文件或加.gitignore不能清除历史。
2. 审查docs/UPSTREAM.md中的许可范围；个人新增部分尚未自动统一授权，确认许可证后再公开分发。
3. 运行tools/review-public.py，检查报告；扫描只是辅助，不保证检出所有秘密。人工检查git diff和待提交文件。
4. 保留web/bun.lock与plugin/go.sum，排除node_modules、dist、编译器、缓存、截图、历史数据库和备份。
5. README示例仅使用回环地址与占位服务器名；不要提交自己的SSH配置、私钥、VPS地址、Webshare账号或机场订阅。
6. 保持当前单一main流程：小范围改动经差异、敏感信息与测试检查后再提交推送。只有需要并行开发或独立审查时才创建短期分支，不要直接把运行目录的全部历史推上去。
7. GitHub Actions只跑离线/模拟检查，不给CI放生产管理密钥，不自动部署、OAuth登录或消耗模型额度。
8. Git排除与Docker构建排除分别检查：插件状态、Auth、数据库、密钥和日志不进入构建上下文；deploy/assets中的已构建网页、deploy/vendor中的已校验后端及insights/pricing.json是必要构建输入，不能一并排除。

## 源码整理范围

保留能够验证业务规则、兼容性和回归问题的测试，以及上游许可证、锁文件与维护文档。临时测速、浏览器录屏、私人排查脚本、编译器缓存和运行数据放在仓库之外；不能仅凭文件名包含test或probe就删除上游测试。

整理前记录Git状态并备份相关文件；整理后检查跟踪变更和未跟踪文件。格式调整可以用Python AST和JSON解析结果对照，再运行相关测试。只清理生成物不代表可以改变运行服务、数据库或用户配置；源码整理提交无需重新部署VPS。

git push、创建远端仓库、配置GitHub Secrets与部署需获得当前任务授权。依赖数量精简不意味着删除实际使用的库；更换编辑器/路由/动画库属于另一个重构任务。
