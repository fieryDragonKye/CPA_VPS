# 方案比较与研究交付

按实际决策填写，单一事实无需强行制作大表。

| 维度 | 需要确认的内容 |
|---|---|
| 功能匹配 | 必须具备的真实能力、限制、替代路径 |
| 环境兼容 | 当前框架/依赖/系统/协议版本，浏览器与部署条件 |
| 成熟度 | 近期发布、维护响应、已知缺陷、测试与复现质量 |
| 许可证 | 仓库实际 LICENSE、具体版本、依赖及商业使用/再分发约束；不确定则待核实 |
| 成本 | 集成、迁移、运维、学习、依赖、内存/性能、服务收费 |
| 风险与回滚 | 数据与认证边界、供应商限制、退出与恢复方式 |
| 验证 | 当前已执行、还需测试、最小隔离实验和成功标准 |

以当前环境推荐，避免无依据打分。结论分为已证实事实、来自他人环境的经验、推断与待验证。记录排除选项的实际原因，不只列优点。

实施授权与研究授权分开：建议升级、安装或部署前说明具体改动和验证/回滚范围；用户已明确授权的后续实施不重复索要同一许可。没有证据支持某项功能时，选择保留不确定性，不编造可用接口。
