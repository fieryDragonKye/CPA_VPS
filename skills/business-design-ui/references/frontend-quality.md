# Frontend Engineering Quality · 1.0.0

本文件不包含私人主题。两个 UI Skill 各自携带完全相同的分发副本，维护源位于本次安装维护目录；不要跨 Skill 运行时读取另一套视觉规则。

## 范围、真实性与实现

- 先检查实际技术栈、组件、业务与当前授权，沿用现有设计系统。小修复不扩展成重构，不因参考图增加虚构功能、数据、背书或统计。
- 修改前记录 Git 状态并保存必要基线；未跟踪文件和非 Git 目录核对实际内容/哈希。最终区分用户原有改动、本次源码、生成产物和诊断材料。
- 语义化 HTML、可复用组件和语义色彩角色优先。无需为普通页面增加新框架、动画库或大型依赖。

## 稳定布局与可访问性

- 按内容验证 320、360、768、1440px 等代表宽度，适应长文本、翻译与缩放。数值是常用检查点而非所有项目的固定设备目录。
- 检查 Flex/Grid 子项最小宽度、内部滚动和祖先 overflow；不用全局隐藏横向溢出掩盖问题。局部表格滚动应可发现并支持键盘访问。
- 加载图标、错误提示和字体变化不能无意推挤关键操作；明确首载、后台刷新、空态和失败。缓存需有作用域、失效及竞态策略，不缓存敏感凭据。
- 使用真实标签、恰当按钮/链接语义、可见键盘 Focus 和可操作状态；不把静态信息伪装成控件。不全局禁止选区或移除焦点。
- 检验 Hover、Focus、Active、Disabled、Loading 及错误态；触控目标按使用场景充分留空间，不机械放大全部字号。
- 普通文字对比度目标 4.5:1、大字 3:1；这不代表全部无障碍合规。透明背景按最亮/最暗实际叠加状态检查，不只测静态色块。
- 验证行高、字形盒、裁切、图标留白；原生浏览器缩放与 DPR/CSS zoom 区分。截图检查须核对实际像素区域。

## 动画与性能

- 非必要动画尊重 prefers-reduced-motion；透明材质尊重 prefers-reduced-transparency，并有 backdrop-filter 不可用时的可读替代。
- transform/opacity 通常是优先候选，但不保证合成无成本。根据测量定位滤镜、阴影、纹理、层数、布局和脚本，勿全局硬件加速或盲删视觉效果。
- 实际卡顿时分开测试持续动画、滚动、导航、Hover 与刷新；记录设备、刷新率和环境，条件可比时重复 A/B。
- rAF 分位数不等于物理呈现帧率；Trace 有测量开销；单次峰值不代表全部性能。不能把未测 GPU/内存数值写成实测。

## 交付证据

按改动执行适当测试、Lint、类型和构建检查，避免没有意义的镜像实现测试。随后检查真实渲染、键盘、响应式、降级和改动影响的功能。

构建通过不代表视觉达标；浏览器模拟不代表真机/真实接口；DevTools 注入不代表最终发布。获准发布时核对构建、静态文件与在线内容一致，不因前端修改擅自重启服务。

明确列出已执行、未执行及局限；静态检查、截图、计算样式、性能和真实业务验证分别陈述。不声称未经验证的兼容性、无障碍认证或所有设备 60fps。
