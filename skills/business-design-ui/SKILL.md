# Business Design UI

仅在用户显式选择本 Skill 或输入 $business-design-ui 时使用。不自动加载私人 UI Skill，不因用户拥有该项目而引入私人流光主题。

根据具体业务、目标用户、品牌、内容与现有产品选择设计方向。商业不等同于统一的商务蓝或白色卡片：极简、编辑式、科技、电商、活泼品牌等都可成立，必须说明与本项目的关系。

## 工作方式

1. 读取实际技术栈、品牌资料、页面任务和已有组件。新项目优先确定信息架构、关键动作、内容密度与可信表达；关键信息缺失时只询问影响决策的问题。
2. 选择一种主视觉语言，并明确排版、色彩角色、表面材质、布局与动效强度。用户没有指定风格时依据业务提出合理方向，不默认深蓝、青蓝流光或多层玻璃。
3. 在现有架构中实现授权范围的改动。保留真实功能、数据与交互，不为审美重建无关后端或引入不必要依赖。
4. 用真实浏览器检查内容层级、响应式、状态反馈及可访问性。视觉审查与功能测试分别给结论，不用通过构建代替视觉验收。

## 按需资料

- 确定需求和视觉方向时，读 [需求与风格选择](references/brief-and-style-selection.md)。
- 需要比较设计手法时，读 [风格与业务模式](references/style-patterns.md)，不要把示例当成限定风格目录。
- 页面实现与交付检查，读 [前端工程质量规范](references/frontend-quality.md)；小修复只使用相关部分。

## 边界

品牌若明确要求蓝色、玻璃或动态效果，可以采用，但须由当前需求支持，并检验可读性与成本。没有私人主题的默认参数，不读取另一套 Skill 来补齐样式。不编造客户背书、交易数据、合规认证或产品能力；示例数据需明确标识。对未执行的浏览器、性能和无障碍测试如实说明。
