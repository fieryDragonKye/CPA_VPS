# 证据与隔离实验

## 建立足够而不过量的基线

记录系统、实际程序/依赖版本、启动方式、页面/请求、数据规模、权限、时间范围和复现概率。使用已有资料时核对它是否对应当前产物。优先复用可靠证据，避免重复大规模测试。

修改前记录相关仓库 Git 状态；未跟踪内容和非 Git 文件用备份/哈希补充。最终核对磁盘、Git 差异、新增文件及用户原有改动，不能把空 diff 当作未改文件的证明。

## 因果实验

为每个假设写支持/反对证据、隔离变量和可观察预测。A/B 尽量保持硬件、浏览器、数据、视口、预热与操作相同；必要时交错顺序或 A/B/A。工具开销不同的样本不能随意合并。

如仅授权只读：浏览器临时样式、模拟数据或隔离副本也须符合本次范围；不得把临时补丁写入正式源码，不启动未授权服务。模拟接口不证明真实业务链路。主动请求可能产生费用或数据写入时先核对权限，不因“测试”就视为无副作用。

## 最小修复与回归

用户已经给出可靠诊断和明确修改范围时，核对证据仍适用后直接做授权的小修复，不重新设计流程。优先改最接近根因的组件，避免全局覆盖、遮罩、固定延迟和大范围缓存掩盖问题。

根据风险验证边界：首次与重复、空与错误、键盘、移动、身份隔离、异步竞态、实际产物。单纯可逆小样式修复无需制造大量镜像实现的测试。记录可回滚的原文件与实际 diff，不擅自删除用户其他改动。

交付结论包括：最支持的根因与可信度；定位路径；已执行结果；尚缺证据；最小修改/副作用；验证与回滚。无法确认根因不等于可以猜测修复。
